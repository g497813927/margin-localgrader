Margin / Local rubric grader

One place to get started.

Start with an empty rubric, add your own criteria, and configure local models for reviewing one submission at a time. This guide works as a local file before the app is running.

Use Python 3.12 on Windows, Linux, or macOS. The image workflow uses portable Pillow/PDFium processing and a local Ollama service; Apple Vision is not required. GPU acceleration depends on the installed runtime and hardware; CPU operation is slower. Automated tests run on macOS and in a fresh Linux container. Windows launcher branches have simulated tests and a native Windows CI job; native Windows execution still needs verification. Installation downloads are separate from grading, which uses local files and loopback services.

Node.js is needed only for the optional frontend tests. Use the patched 26.12.1 release pinned in .node-version; normal grading requires Python, not Node or npm. To update an existing Python environment after pulling changes, activate it and run python -m pip install --upgrade -r requirements.txt, then restart Margin.

01 / Install once

Start with the application.

Prerequisites: Git, Python 3.12, and enough free space for your selected models. Node.js is needed only for frontend development tests. On Linux, install your distribution's Python 3.12 and matching venv package. On Windows, use the Python installer with the py launcher. On macOS, the official installer or Homebrew python@3.12 works.

Copy the clone URL from GitHub's Code button and replace REPOSITORY_URL:

git clone REPOSITORY_URL margin-public
cd margin-public

A source ZIP also works: extract it and open a terminal in that folder. Create and activate an environment for your operating system:

macOS / Linux · Terminal
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
Windows · PowerShell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

If PowerShell blocks activation, no policy change is necessary: replace python in every later command with .\.venv\Scripts\python.exe. For example:

.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py

All commands below run inside this project with its environment activated. In each new terminal, activate it again. No other checkout, existing model cache, account, or saved workspace is needed.

For the smallest working grading setup, install Laya:

python scripts/setup_laya.py --install-deps

This installs pinned dependencies and approximately 680 MB of weights in models/laya-multilingual. Allow several GB for the environment. You can choose another decision model below; the app opens before weights are installed.

Start Margin:

python run.py

Open http://127.0.0.1:8765/. Keep the terminal open; Ctrl+C stops the app and servers started by its workspace. macOS also provides Start Margin.command. Startup never installs packages or downloads models.

Complete internet-connected setup before working with student records. Model weights and environments are not included in the repository. Image recognition is optional and requires the separate vision setup below.

02 / Configure in the browser

Your model workspace.

  1. Expand Model workspace. Use the search input to find Laya, Clef, StartLux, Decision 3.0 Mini, or your current custom entries. This search stays local; it does not query an online model catalog.
  2. Add a preset or choose ＋ Custom local server. Expand Connection and scoring settings to edit its display name, Inference provider, model identifier or local path, endpoint, and scoring controls. Use each entry’s checkbox to enable it and the ↑ / ↓ buttons to arrange its order. You can keep up to eight entries and grade with one to eight enabled models.
  3. Install bundled model files below, then press Start for the corresponding server. Once ready, press Check enabled models. Laya runs inside Margin and has no separate server switch.
  4. Under Model workspace, keep Automatically detect visual content in uploaded PDF and Word submissions enabled to review text and visuals from one normal submission upload. This is on by default. Choose the installed vision model here; turn detection off for text-only document imports. Detection prepares a preview and never starts model inference automatically.
  5. Save workspace writes only model, explanation, and vision settings to config/model-workspace.json. New pages restore that explicitly saved configuration. Load saved rereads it; Import configuration validates settings JSON in memory; Export configuration downloads a settings-only copy. Changes are not autosaved.
  6. The × button removes a workspace entry. It does not delete weights or stop a server. Use Stop separately to release server resources, then save the updated configuration.

First run with Laya only: uncheck Clef, StartLux, and Decision 3.0 Mini, leave Laya enabled, and turn off Local explanation review until you install an explanation model. Press Check enabled models, then Save workspace. The four presets are suggestions, not four preinstalled models.

Bundled controls use fixed local launchers and ports. A server started in another Terminal is shown as external; stop it in that original Terminal. The app only stops processes it started. When another copy of Margin is already running, its model servers also appear as external here.

Workspace files contain no assignment, rubric, submission, grade, review note, or grading history. Rubric and result exports remain separate, deliberate actions. Use model labels only in configuration fields.

Add a custom decision model

Under Inference provider, choose System One · local decision server for an installed local service implementing the supported decision protocol, then enter its exact model identifier and http://127.0.0.1:PORT/v1/systemone endpoint. Or choose Laya · embedded offline model with a compatible local checkpoint folder. A generic chat-completions or Ollama endpoint is not a decision-model adapter.

Launch custom servers separately. The UI does not execute arbitrary shell commands. Ensure custom servers use local weights, disable logging, and never forward requests. Remote addresses, redirects, and environment proxies are rejected by the grading client. Renaming the same model does not make it an independent second model.

Optional / Explain the suggestions

Qwen3.8 local review.

The preset explanation model is qwen38-27b:q4_k_m, with thinking off. It explains disagreements or unanimous deductions when all selected decision models (at least two) return valid rubric levels. Model points and instructor scores stay unchanged.

After completing the optional setup below: use Start for the explanation service in the workspace. Its private Ollama daemon uses port 11435, separate from personal Ollama on 11434. You can enter another model already installed in this private cache in the explanation settings.

Install the optional explanation model

Install the tested Ollama 0.40.5 runtime from its official release. The launcher accepts the reviewed versions 0.40.3 and 0.40.5 and checks the server’s cloud-disabled status. No sign-in, pre-existing models, DeepSeek baseline, or saved configuration is required. Ollama may create its standard local identity under ~/.ollama on first use; Margin keeps model weights separately under this project’s models/ollama-explanations.

The launcher finds ollama on its fixed PATH, inside /Applications/Ollama.app on macOS, or in %LOCALAPPDATA%\Programs\Ollama on Windows. For another location, manually use --ollama with the quoted full executable path. The workspace also searches .venv/Scripts on Windows and .venv/bin on macOS/Linux. You do not need to launch Ollama’s desktop app or its normal port 11434 service.

macOS/Linux advanced option: the verified Qwen3.8 GGUF downloader below uses POSIX file operations and does not run natively on Windows. Windows users can install a compatible local vision/chat model with the portable setup in the next section and enter its exact name in explanation settings. Explanation quality for that alternative is not benchmarked here. Download Qwen during setup, then start the empty private daemon:

python scripts/setup_explanation_candidates.py --candidate qwen38 --workers 16
python scripts/run_ollama.py

Leave that Terminal running. In a second Terminal in this same project folder, import the verified weights:

python scripts/import_explanation_candidate.py --candidate qwen38

Allow at least 33 GB free disk space for Qwen’s 16.46 GB download plus its separate model-store copy, and additional memory for inference. Import verifies the file checksum and confirms the daemon is using this project’s model store before creating the alias. No APFS cloning or personal model cache is required.

After a successful import, stop the manually launched daemon with Ctrl+C. In Margin, use the explanation service’s Start button, enable Local explanation review, and keep the model name qwen38-27b:q4_k_m. The workspace can manage subsequent starts. These controls do not install, import, or download anything. Leave explanations off on machines that cannot hold this model.

If a comparison proof expires or the app restarts, grade again to authorize a fresh explanation. Retry an unavailable explanation without replacing the original model scores.

Optional / Read visual submissions

Images and diagrams, on every platform.

The same local Ollama API is used on Windows, Linux, and macOS. The initial small-model preset is openbmb/minicpm-v4.7:1b (about 1.8 GB of model downloads); qwen3.5:2b-q4_K_M (about 1.9 GB) is an alternative. Runtime memory is higher than download size. These are candidates, not a measured accuracy ranking. MiniCPM's unqualified/default tag selects a much larger model; keep the explicit :1b tag.

  1. Install the reviewed Ollama 0.40.5 release for your operating system. The launcher accepts the reviewed versions 0.40.3 and 0.40.5 and checks cloud-disabled status. Do not loosen the version guard to make an unsupported model load.
  2. In one activated project terminal, start the private service:
python scripts/run_ollama.py

This uses 127.0.0.1:11435 and the project store models/ollama-explanations. It starts empty and never downloads by itself. If the workspace already started this same service, use that running instance instead.

In a second activated project terminal, explicitly download the selected public model during setup:

python scripts/setup_vision.py --model openbmb/minicpm-v4.7:1b
python scripts/setup_vision.py --model openbmb/minicpm-v4.7:1b --offline

Alternative:

python scripts/setup_vision.py --model qwen3.5:2b-q4_K_M

The setup script verifies the daemon's private store, cloud-disabled status, and local vision capability. It sends only the public model tag, never a student image. Download progress contains no student content. A successful metadata check does not establish accuracy or guarantee that every new architecture loads on the pinned runtime; test with a non-student diagram first. A model requiring a newer runtime is rejected. There is no cloud or text-only fallback.

Stop the manual daemon with Ctrl+C if you want the workspace to manage it. In Margin, use the local Ollama service's Start button; vision and explanations share that one service and load one model at a time. The image feature does not require enabling explanation review.

  1. In Model workspace, select the installed vision model and leave automatic visual detection enabled. Selection never downloads weights. Save the workspace only if you want to reuse these settings.
  2. Use the normal Choose a submission upload once for TXT, PDF, DOCX, PNG, JPEG, or WebP. For PDF/Word documents, text is extracted and detected visual content automatically opens in Images and diagrams; no second upload is needed. Direct image uploads open the image preview. TXT uploads need no visual processing.
  3. Inspect the first preview, then use Detected visual content to select another embedded image or vector page. PDF screenshots are extracted separately instead of shrinking the whole page around them; Visual on this PDF page switches between embedded images and the page layout. Detection may miss some visuals; use the page/image controls or manual visual upload when needed. Turning off automatic detection keeps normal PDF/Word uploads text-only.
  4. Press Analyze locally. The default Read detailed crops setting analyzes an overview and overlapping regions sequentially; turn it off in Model workspace for a quicker single-view read. Compare the editable Transcribed text and Visual description against the image, and expand the individual drafts when regions disagree. If a view fails to finish, completed views remain available with an explicit partial-reading warning; unread regions are not missing student work. Native PDF text is preserved directly, including SQL punctuation; a vector page with native text produces a visual description rather than replacement OCR. Correct labels, chart values, and relationships before approving.
  5. Check the review box, then Add reviewed content to submission. Existing submission text is preserved. Previous grades are cleared because the submission changed; press Grade again when ready. Recognition itself never changes model or instructor scores.

Images and extraction drafts remain in memory and clear with Next student. Only reviewed text reaches the decision models. Treat uncertain handwriting, small labels, and inferred relationships as requiring inspection; a failed extraction is not an automatic zero.

PDF text is extracted directly and never rewritten by the vision model. Embedded raster images are extracted at their own resolution; pages with vector drawings are rendered locally. Sources retain up to 4,096 pixels per side for detail crops. Small or blurry originals may still lack recoverable text, and crops can disagree or omit cross-region relationships. DOCX support covers embedded raster images, not a full Word layout engine: convert documents containing Word shapes, SmartArt, charts, or vector drawings to PDF to preserve their appearance. Linked external images are never fetched. Large files/pages and unsupported formats are rejected rather than silently truncated; crop or split them locally. For lower memory use, analyze one page at a time and stop unused decision servers.

04 / Grade one submission

A simple daily workflow.

  1. Start the app and the enabled local servers; check their connections.
  2. Enter the assignment and build your rubric using Add a criterion, or import your own rubric JSON. The title, guidance, and criteria start empty. Optional Instructor grading guidance also starts empty; enter your own policy if needed. Your guidance remains active when collapsed.
  3. Paste one student's text or use Choose a submission once for TXT, PDF, DOCX, PNG, JPEG, or WebP. Automatic detection is on by default: PDF/Word text is extracted and detected visuals open for review. Press Analyze locally, check the transcription and description, then explicitly add reviewed content before grading. Turn automatic detection off in Model workspace for text-only document imports. Legacy .doc needs conversion first.
  4. Grade and compare the enabled models' original levels and separate explanation. Review thresholds flag uncertainty without deducting points. Failed model responses remain unavailable.
  5. Enter your score and notes. Export a result only when you want a deliberate local file. Next student clears the current submission/results while retaining the assignment and rubric in memory.

Reloading or closing clears unsaved work. Saving model settings does not save student work. Margin does not upload grades to Canvas or keep grading logs.

When something needs attention

Quick checks.

SymptomAction
External serverUse it as configured, or stop its original Terminal before pressing Start. Margin will not take over or kill it.
Startup errorCheck installed weights and compatible runtime. Run the fixed launch command above for setup diagnostics. It never downloads missing files.
Still startingAllow time for verification and model loading, then refresh server status. Only run the models your machine can hold.
Duplicate modelA renamed label is not a new model. Select a different checkpoint/server configuration or disable the duplicate.
Custom connection failsCheck the loopback URL, exact model ID, and SystemOne decision protocol. There is no cloud fallback.
Saved settings fail to loadDefaults remain available in memory; the bad file is untouched. Import valid settings or explicitly Save. Correct unsafe symlinks/permissions locally first.
App port occupiedmacOS/Linux: MARGIN_PORT=8766 python run.py. Windows PowerShell: $env:MARGIN_PORT="8766"; python run.py. Then open port 8766. Model ports remain fixed.
Vision model unavailableCheck the private Ollama service on 11435, the exact installed vision tag, and python scripts/setup_vision.py --model MODEL:TAG --offline. Do not use the personal 11434 store. A runtime/architecture failure needs a compatible model or a reviewed runtime update.
App updated with old tabs openPreserve needed work, then open a fresh page. Old tabs keep old controls; do not reload unfinished work.

Bundled inference uses local weights, disabled logs, and loopback services. Custom servers, browser extensions, OS swap, backups, and deliberate exports remain under your control. Local-only operation is an implementation property, not a FERPA certification.
